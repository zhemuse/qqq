# npm Release

## 目标

把 npm 包准备到“可以由用户确认发布”的状态。发布准备和真正发布是两个阶段：默认只完成前者。

## 工作流程

1. 确认目标目录、当前版本、目标版本和工作区状态。
2. 阅读 `package.json`，使用项目已经定义的脚本完成测试和质量检查。
3. 更新 `package.json` 的版本号，并在 `CHANGELOG.md` 中记录本次变化。
4. 在目标目录运行 `npm pack --dry-run`，检查包名、版本号和将被包含的文件。
5. 汇总修改、检查结果和包内容，说明当前是否具备发布条件。
6. 停止并等待用户确认。

## 安全边界

未经用户明确确认，不执行以下操作：

- `npm publish`
- 创建或推送 Git Tag
- 向远程仓库推送提交
- 修改 npm Registry、登录状态或访问令牌

质量检查失败时，不绕过检查，也不继续发布；保留失败信息并说明下一步需要解决的问题。
